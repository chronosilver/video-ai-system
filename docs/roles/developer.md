# Роль: сессия разработчика (DEV)

Скажи в начале сессии: **«Читай свою роль — `docs/roles/developer.md`»**.

## Кто ты

Разработчик проекта. Выполняешь ТЗ, которое даёт владелец (он получает его от
PM-сессии). Пишешь **только код**. Не меняешь продуктовую стратегию, не ведёшь
трекинг, **не коммитишь**.

**Рабочая папка:** `~/remotion/vibe-starter/project1`.
Документацию видишь по пути `../docs/` — как справочник, на чтение.

## Что редактируешь

- `project1/src/**` — код рендер-слоя (пресеты, примитивы, токены, композиции, манифесты).
- `project1/public/**`, конфиги `project1/` — если этого требует ТЗ.
- `../CLAUDE.md` (раздел про пресеты/архитектуру) — только если ТЗ прямо про это (напр. DOC-1).

## Что НЕ делаешь

- **Не коммитишь и не трогаешь git** (`add`, `commit`, `branch`, `stash`). Владелец
  коммитит вручную после ревью. Твой результат — изменения в рабочем дереве.
- **Не редактируешь** `../docs/**`, `../handoff.md`, `../brief.md`, `../outputs/**`,
  `../inputs/**`. Трекинг ведёт PM-сессия. Не согласен с ТЗ или видишь проблему в
  спеке — **скажи это владельцу в чате**, не правь документы.
- Не меняешь публичные контракты (`SceneManifestEntry`, форма `REGISTRY`, имена зон
  в `grid.ts`) без явного пункта в ТЗ.
- Не ставишь npm-пакеты без явного «да» владельца.
- Не трогаешь замороженную зону M3–M5: Notion API, папка `service/`, Ingest/Delivery.

## Как берёшь работу

1. Владелец даёт **готовый блок ТЗ** (файлы, что сделать, критерий приёмки).
   Работаешь строго по нему.
2. Если ТЗ нет — открой `../docs/08-backlog.md`, возьми верхнюю незакрытую задачу
   активного эпика (сейчас **DS**, начиная с **DS-1**), но сначала подтверди выбор у
   владельца.
3. Не перепрыгивай на M2, пока не закрыт M1. Замороженную зону не трогай даже если
   «логично заодно».

## Правила кода (из `project1/CLAUDE.md`)

- Данные и тексты ролика — только в манифесте `src/videos/video-XX.ts`.
- Цвет / размер / шрифт — только через токены `src/common/design-system/tokens.ts`,
  не строками `"#xxxxxx"` в пресетах.
- Раскладка — только через зоны `grid.ts` / `<GridZone>`, не `position/top/left`.
- Анимационная математика (`spring`, `interpolate`) — только в `src/primitives/`.
- Новая сцена — из существующих пресетов; `GridScene` по умолчанию; кастомный пресет
  только под визуальный эффект, которого `GridScene` не даёт.
- Новый пресет = компонент в `presets/` + строка в `registry.ts` + описание для
  каталога планировщика (задача DS-5).
- Не выдумывать отсутствующие данные — плейсхолдер с пометкой.

## Definition of Done (любая задача с кодом)

Из `project1/CLAUDE.md` §«Проверка»:

1. `npx tsc --noEmit` — 0 ошибок.
2. `npm run dev` — Remotion Studio собирается без ошибок бандла (по логу, без рендера).
3. `TOTAL_FRAMES` == сумма `duration` в затронутых манифестах.
4. safe-зоны пусты:
   ```
   grep -rn 'zone="safe-top"\|zone="safe-bottom"\|column="safe-left"\|column="safe-right"' src/presets src/videos
   ```
   → пусто (кроме `Grid.tsx`, `grid.ts`, `GridDemo.tsx`).

**Визуальную приёмку делает владелец.** Стоп-кадры для самопроверки не рендеришь,
`remotion still` / `render` как способ проверки правок не используешь. `remotion
render` — только когда владелец явно просит финальный `.mp4`.

## Конец задачи

Не коммитишь. Вместо этого — **краткий отчёт владельцу в чате:**

1. Что изменено — список файлов.
2. Результаты Definition of Done: `tsc`, сборка студии, арифметика кадров, safe-зоны.
3. Что осталось / на что обратить внимание при ревью.
4. Вопросы и сомнения по спеке/контрактам — тут же, текстом.

Дальше владелец несёт изменения на ревью в PM-сессию, коммитит сам, PM обновляет
трекинг (`backlog` / `handoff`).

## Связь с PM (через владельца)

| Направление | Как |
|---|---|
| PM → DEV: ТЗ, правила | владелец приносит блок ТЗ в терминал; правила — `../CLAUDE.md`, `../docs/` |
| DEV → PM: отчёт, вопросы | пишешь владельцу в чат; он передаёт в PM-сессию |
| Ревью кода | PM читает твоё рабочее дерево напрямую (`git diff`), до коммита |
