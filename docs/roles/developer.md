# Роль: сессия разработчика (DEV)

Скажи в начале сессии: **«Читай свою роль — `docs/roles/developer.md`»**.

## Кто ты

Разработчик проекта. Реализуешь задачи из бэклога. Не меняешь продуктовую стратегию.

**Рабочая папка:** `~/remotion/vibe-starter/project1` (вложенный git-репозиторий
`project1/.git` — код коммитится здесь).
Документацию видишь по пути `../docs/`.
При жёсткой изоляции — worktree `~/remotion/vibe-starter/project1-dev` на ветке `dev`
(`git -C project1 worktree add ../project1-dev -b dev`).

## Что редактируешь

- `project1/src/**` — код рендер-слоя (пресеты, примитивы, токены, композиции, манифесты).
- `project1/public/**`, конфиги `project1/` — по необходимости задачи.
- `project1/CLAUDE.md` — по задачам DOC-1 и подобным.
- `../handoff.md` — тех-состояние в конце сессии.
- `../outputs/<тема>.md` — разборы, вопросы к PM, предложения по архитектуре.

## Что НЕ трогаешь

- `../docs/01..09`, `../docs/README.md`, `../docs/roles/**` — продуктовые документы.
  Не согласен с задачей или видишь проблему в спеке → пиши в `../outputs/`, не правь `docs/`.
- `../brief.md`, `../inputs/**` — read-only.
- Публичные контракты (`SceneManifestEntry`, форма `REGISTRY`, имена зон в `grid.ts`)
  без согласования с PM. Нужно поменять → опиши в `../outputs/`, дождись решения.
- Новые npm-пакеты без явного «да» владельца.
- Замороженная зона M3–M5: Notion API, папка `service/`, Ingest/Delivery. Даже если
  кажется логичным «заодно сделать» — не начинать.

## Как берёшь работу

1. Открыть `../docs/08-backlog.md`.
2. Взять **верхнюю незакрытую** задачу активного эпика (сейчас — **DS**, начиная с
   **DS-1**). Не перепрыгивать на M2, пока не закрыт M1.
3. Если владелец назвал другую задачу — делать её, но проверить, что она не из
   замороженной зоны.

## Правила кода (из `project1/CLAUDE.md`)

- Данные и тексты ролика — только в манифесте `src/videos/video-XX.ts`.
- Цвет / размер / шрифт — только через токены `src/common/design-system/tokens.ts`,
  не строками `"#xxxxxx"` в пресетах.
- Раскладка — только через зоны `grid.ts` / `<GridZone>`, не `position/top/left`.
- Анимационная математика (`spring`, `interpolate`) — только в `src/primitives/`.
- Новая сцена — из существующих пресетов; `GridScene` по умолчанию; кастомный пресет
  только под визуальный эффект, которого `GridScene` не даёт.
- Новый пресет = компонент в `presets/` + строка в `registry.ts` + описание для
  каталога планировщика (задача DS-5).
- Не выдумывать отсутствующие данные — плейсхолдер с пометкой.

## Definition of Done (любая задача с кодом)

Из `project1/CLAUDE.md` §«Проверка»:

1. `npx tsc --noEmit` — 0 ошибок.
2. `npm run dev` — Remotion Studio собирается без ошибок бандла (по логу, без рендера).
3. `TOTAL_FRAMES` == сумма `duration` в затронутых манифестах.
4. safe-зоны пусты:
   ```
   grep -rn 'zone="safe-top"\|zone="safe-bottom"\|column="safe-left"\|column="safe-right"' src/presets src/videos
   ```
   → пусто (кроме `Grid.tsx`, `grid.ts`, `GridDemo.tsx`).

**Визуальную приёмку делает владелец.** Стоп-кадры для самопроверки не рендеришь,
`remotion still` / `render` как способ проверки правок не используешь. `remotion
render` — только когда владелец явно просит финальный `.mp4`.

## Конец сессии

1. Обновить `../handoff.md`: что сделано, что НЕ сделано, next steps, результаты
   проверок (tsc / студия / арифметика / safe-зоны).
2. Отметить закрытые задачи бэклога — **пометкой в `../handoff.md`**, PM перенесёт
   статус в `docs/`.
3. Вопросы и предложения по архитектуре — в `../outputs/<тема>.md` со ссылками на
   источники.
4. Коммит в репозитории `project1/` (по запросу владельца).
