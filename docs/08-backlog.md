## Эпик DS — дизайн-система под ключ (M1)

### DS-1 🔴 Флип токенов на светлую тему
- **Область:** `project1/src/common/design-system/palette.ts`, `tokens.ts`, `scale.ts`.
- **Что:** по `about.md` §3–§7 — `palette` → базовая `paletteLight`; `color.*`
  (bg `#FFFFFF`, text `#141414`, серая лестница `textMuted`/`textFaint`, `accent`
  только заливка + `accentInk` `#4C9A00` + `textInverse`); `scale.fontSize`
  150/96/60/36/28/22; `spacePx` / `radiusPx` по гайдлайну; `elevation` без glow.
- **Приёмка:** `npx tsc --noEmit` = 0; `DesignSystemDemo` (DS-3) показывает светлую
  палитру; `about.md` §7 обнулён (расхождений нет).

### DS-2 🔴 Пересбор хардкод-цветов в пресетах
- **Область:** `project1/src/presets/*` (в первую очередь `HookScene`, `DocumentList`,
  `SlideInList`; проверить все 9).
- **Что:** убрать `rgba(255,255,255,…)`, `#1e1b4b`, тёмные градиенты, `color.accent`
  как цвет текста → на `color.*` / `accentInk` под белый фон.
- **Приёмка:** `grep -rn '#[0-9a-fA-F]\{3,6\}\|rgba(' src/presets` — только осознанные
  исключения; каждый пресет виден в студии на белом фоне (проверяет пользователь).

### DS-3 🟡 Композиция `DesignSystemDemo`
- **Область:** `project1/src/compositions/DesignSystemDemo.tsx`, `Root.tsx`.
- **Что:** по образцу `GridDemo.tsx` — свотчи всех `color.*`, все роли `text.*`
  строками-примерами, `radius` / `stroke` / `elevation`. Статичная (0 анимации).
- **Приёмка:** появляется в студии; правка токена сразу видна на демо.

### DS-4 🟢 Файлы шрифта SF Pro Display
- **Область:** `project1/public/fonts/`.
- **Что:** положить `.woff2` (Thin / Light / Regular) по инструкции
  `public/fonts/README.md`. Проприетарный Apple — файлы приносит пользователь.
- **Приёмка:** заголовки в студии рендерятся SF Pro Display, не fallback.

### DS-5 🟡 Меню пресетов для планировщика
- **Область:** рядом с каждым пресетом — короткое описание (назначение, форма `data`,

- **Что:** структура, которую шаг A планировщика получит в промпте. Формат — JSON

- **Приёмка:** `PRESET_CATALOG` покрывает все ключи `REGISTRY`; тест «каждый пресет

## Эпик REND — headless-рендер (M2)

### REND-1 🔴 Node-обёртка рендера
- **Область:** `service/render/`.
- **Что:** `@remotion/renderer` через Node API — `selectComposition` + `renderMedia`
  с `inputProps: { manifest }`. Опции явно (`imageFormat: "jpeg"`, `overwrite`,
  tailwind через webpack override — CLI-конфиг в Node не применяется).
- **Приёмка:** `renderVideo(manifest) → out/video-<id>.mp4` 1080×1920 30fps;
  логируется длительность рендера.

### REND-2 🟡 Валидатор
- **Область:** `service/validator/`.
- **Что:** прогон чек-листа из `CLAUDE.md` в порядке дешевизны: арифметика кадров →
  `grep` safe-зон → `tsc --noEmit` → сборка. Возврат `{ ok, failures[] }`.
- **Приёмка:** ломаный манифест (битый `data`) → `ok: false` с понятной причиной,
  рендер не вызывается.

### REND-3 🟢 Кеш рендера
- **Что:** `sha256(manifest)` → пропустить рендер, если файл уже есть. (M5, но заложить
  интерфейс раньше.)

## Эпик PLAN — планировщик (M2–M3)

### PLAN-1 🔴 Контракт входа и нормализация
- **Область:** `service/ingest/normalize.ts` (используется и в M2 из файла, и в M3 из Notion).
- **Что:** текст → `scriptBlocks[]` (split по пустой строке / `---`), `comments[]`
  (по строкам), извлечение `brandPreset` / `targetDuration`.
- **Приёмка:** эталонный `script-01.md` (= сюжет `video-01`) → 6 блоков; юнит-тесты
  на разделители.

### PLAN-2 🔴 LLM-шаг раскладки (шаг A)
- **Область:** `service/planner/plan.ts`.
- **Что:** промпт с меню пресетов (DS-5), правилами из `CLAUDE.md`, эвристиками
  тайминга, комментариями. `openai` structured output → JSON `{ scenes[], unmappable[] }`.
  Цвета/веса модель не задаёт.
- **Приёмка:** на `script-01` выдаёт 6 сцен; ≥ 4/6 пресетов совпадают с эталоном
  `video-01`; `unmappable` пуст.

### PLAN-3 🔴 Детерминированная сборка (шаг B)
- **Область:** `service/planner/build.ts`.
- **Что:** JSON шага A → `SceneManifestEntry[]`: подстановка токенов по ролям,
  `durationSec → кадры`, клампы `[MIN_SCENE, MAX_SCENE]`, подгон к `targetDuration`,
  сериализация в `video-<id>.ts` (или объект в память).
- **Приёмка:** выход проходит REND-2 без правок; `TOTAL_FRAMES` корректен.

### PLAN-4 🟡 Комментарии-патчи + Re-generate
- **Область:** `service/planner/patch.ts`.
- **Что:** распознать императивы (`убери блок N`, `держи дольше`, `preset X вместо Y`,
  `мягче/жёстче`); при `Re-generate` слить с `prevManifest`, не трогая сцены вне
  области комментария.
- **Приёмка:** `video-01` + «убери блок про документы» → 5 сцен, остальные без
  изменений; + «первый держи дольше» → у сцены 1 `duration` на шаг больше.

### PLAN-5 🟡 Набор эталонов и метрика
- **Область:** `service/planner/evals/`.
- **Что:** `script → ожидаемая структура`; прогон, метрика (доля угаданных пресетов,
  отклонение длительности). Запускать при каждой правке промпта.
- **Приёмка:** `npm run eval:planner` печатает таблицу; `video-01` в наборе.

### PLAN-6 🟢 CLI для M2
- **Что:** `npm run generate -- ./inputs/script-05.md` → манифест + рендер + лог.
- **Приёмка:** одна команда даёт `.mp4` из текстового файла.

## Эпик NOTION — интерфейс (M3) — ❄️ ЗАМОРОЖЕН

> Не в работе на текущем этапе. Спецификация ниже — продуманная наперёд цель.
> Приступать только после явного решения пользователя выйти за пределы M1–M2.

### NOTION-1 🔴 База и интеграция
- **Что:** база «Ролики» по `04-notion-workspace.md` (свойства + статусы); internal
  integration, токен из env, доступ только к базе.
- **Приёмка:** сервис читает тестовую строку по API; свойства совпадают со схемой.

### NOTION-2 🔴 Ingest
- **Область:** `service/ingest/`.
- **Что:** поллинг по `Status in {To generate, Re-generate}`; нормализация (PLAN-1);
  `Status = Generating` (лок); задача в очередь; забор `Manifest JSON` при Re-generate.
- **Приёмка:** новая строка `To generate` подхватывается за ≤ интервал поллинга;
  повторный забор той же строки не происходит.

### NOTION-3 🔴 Delivery
- **Область:** `service/delivery/`.
- **Что:** заливка `.mp4` на хостинг (выбрать в M2); запись `Video URL`, `Preview`
  (первый кадр/гиф), `Manifest JSON`, `Render log` (человекочитаемый), `Status`,
  `Iteration += 1`. На любой сбой — `Status = Error` + лог.
- **Приёмка:** после успешного рендера строка в `Done` со ссылкой; при подставленной
  ошибке — `Error` с трейсом.

### NOTION-4 🟡 Очередь и оркестрация
- **Область:** `service/queue.ts`, `service/index.ts`.
- **Что:** последовательная обработка Ingest → Planner → Validator → Render → Delivery;
  один воркер; понятные логи по этапам.
- **Приёмка:** E2E — `To generate` → `Done` без участия человека; лог показывает все
  5 этапов.

### NOTION-5 🟡 Обработка `Needs fix`
- **Что:** `unmappable` не пуст или подгон под `targetDuration` невозможен → `Needs
  fix` + объяснение в `Render log`, без рендера.
- **Приёмка:** сценарий с блоком, который не ложится ни в один пресет → `Needs fix`
  с указанием проблемного блока.
