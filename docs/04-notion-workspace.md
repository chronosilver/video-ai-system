# 04 — Рабочее пространство Notion

Notion — единственный интерфейс пользователя. Ни кода, ни CLI, ни таймлайна —
только строка в базе.

> ❄️ **Заморожено (майлстоун M3).** Ничего из этого файла сейчас не реализуется.
> Документ существует, чтобы Planner в M2 проектировался с учётом будущего входа из
> Notion (те же поля `Script` / `Comments` / `Manifest JSON`). Приступать к
> Notion-интеграции — только после явного решения пользователя.

## База «Ролики» (Reels)

Одна строка = один ролик за всю его жизнь (генерация + итерации правок).

### Свойства (properties)

| Свойство | Тип | Кто заполняет | Назначение |
|---|---|---|---|
| `Name` | Title | пользователь | рабочее название ролика |
| `Script` | Text (или дочерние блоки страницы) | пользователь | **сценарий по смысловым блокам** — см. формат ниже |
| `Comments` | Text | пользователь | короткие пожелания и правки на естественном языке |
| `Brand preset` | Select | пользователь | какой набор токенов (`default` пока единственный) |
| `Status` | Status | оба | машина состояний, см. ниже |
| `Target duration` | Select (`~10s` / `~15s` / `~20s` / `~30s`) | пользователь, опц. | подсказка планировщику по общей длине |
| `Video URL` | URL | сервис | ссылка на готовый `.mp4` |
| `Preview` | Files | сервис | обложка/гиф превью |
| `Manifest JSON` | Text | сервис | сохранённый манифест последней версии (для итеративных правок) |
| `Render log` | Text | сервис | что выбрал планировщик + результат валидации/рендера |
| `Iteration` | Number | сервис | счётчик перегенераций |
| `Updated` | Last edited time | Notion | — |

### Машина состояний (`Status`)

```
            пользователь                    сервис
┌──────────────┐  ставит   ┌──────────────┐  берёт   ┌──────────────┐
│  Draft       │──────────▶│ To generate  │─────────▶│  Generating  │
└──────────────┘           └──────────────┘          └──────┬───────┘
                                                            │
                     ┌──────────────────────────────────────┼───────────────┐
                     ▼                     ▼                 ▼               │
              ┌────────────┐        ┌────────────┐    ┌────────────┐         │
              │   Done     │        │ Needs fix  │    │   Error    │         │
              └─────┬──────┘        └─────┬──────┘    └─────┬──────┘         │
                    │ пользователь        │ пользователь     │ разработчик    │
                    │ пишет Comments      │ правит Script    │ чинит баг      │
                    ▼                     ▼                  ▼               │
              ┌──────────────┐     ┌──────────────┐   ┌──────────────┐      │
              │ Re-generate  │─────│ Re-generate  │───│ To generate  │──────┘
              └──────────────┘     └──────────────┘   └──────────────┘
```

- `Draft` — пользователь ещё пишет.
- `To generate` — готово к первой генерации. **Триггер Ingest.**
- `Generating` — сервис взял в работу (лок от повторного забора).
- `Done` — ролик готов, `Video URL` заполнен.
- `Needs fix` — планировщик не смог разложить сценарий под существующие пресеты
  (`Render log` объясняет, чего не хватило). Мяч у пользователя.
- `Error` — упал tsc / рендер / доставка. `Render log` с трейсом. Мяч у разработчика.
- `Re-generate` — пользователь дал новые `Comments` после `Done`/`Needs fix`.
  **Триггер Ingest** с сохранением непринятых сцен из `Manifest JSON`.

## Формат поля `Script`

Сценарий пишется **по смысловым блокам**, разделитель — пустая строка или `---`.
Один блок ≈ одна сцена. Пользователь не думает про пресеты и кадры.

```
Больше памяти не равно умнее.

У модели 300 токенов контекста против 113 000 в истории переписки.

Больше документов ≠ быстрее найти нужный.
Договор аренды, отчёт, смета, презентация — и где-то среди них нужный.

Мой рабочий процесс:
1. Найти источники
2. Чистый тред
3. Сделать вывод

Меньше шума. Меньше уверенных выдумок.

Guide DAO — AI и crypto на практике. Подпишись.
```

Планировщик сам решит: блок 1 → `HookScene`, блок 2 → `CounterDuo`, блок 3 →
`DocumentList`, блок 4 → `SlideInList`, блок 5 → `BlurReveal`, блок 6 → `HeroBadge`.
(Это ровно `video-01` — используется как эталон для оценки планировщика.)

## Формат поля `Comments`

Короткие императивы, по одному на строку. Планировщик применяет как патчи к манифесту.

```
блок 2 — покажи счётчиком
последний блок сделай мягче
убери блок про документы
первый блок держи дольше
```

Примеры интерпретации:
- «покажи счётчиком» → выбрать `CounterDuo` вместо дефолтного `GridScene`.
- «держи дольше» → увеличить `duration` сцены на шаг.
- «убери блок» → выкинуть сцену, не трогая остальные.
- «мягче / жёстче» → в рамках токенов: сменить `color` роли, убрать/добавить `danger`.

## Что сервис пишет обратно (Delivery)

1. `Video URL` — прямая ссылка на `.mp4`.
2. `Preview` — первый кадр или 2-сек гиф.
3. `Manifest JSON` — финальный манифест (для следующей итерации).
4. `Render log` — человекочитаемо:
   ```
   Сцен: 6 · 500 кадров · 16.7 сек
   1. HookScene (60)   — блок 1
   2. CounterDuo (120) — блок 2, комментарий «счётчиком» применён
   3. DocumentList (90)
   4. SlideInList (90)
   5. BlurReveal (60)
   6. HeroBadge (80)
   tsc: ok · safe-зоны: ok · рендер: ok (42 сек)
   ```
5. `Status` → `Done` / `Needs fix` / `Error`.
6. `Iteration` += 1.

## Доступ и безопасность

- Отдельная **Notion internal integration**, расшарена только на базу «Ролики».
- Токен — в `service/config.ts` из env (`NOTION_TOKEN`), не в репозитории.
- Сервис пишет только в перечисленные свойства. `Script` / `Comments` — read-only
  для сервиса (аналог правила «`inputs/` не менять»).
