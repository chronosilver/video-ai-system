## Слои

### 1. Notion — источник и приёмник (`04-notion-workspace.md`)
База «Ролики». Одна строка = один ролик. Пользователь заполняет: сценарий,
комментарии, бренд-пресет, статус `To generate`. Сервис пишет обратно: ссылку на
`.mp4`, превью, лог, статус `Done` / `Needs fix` / `Error`.

### 2. Ingest — забор задач
- Поллинг Notion API (или webhook позже) по фильтру `Status in {To generate, Re-generate}`.
- Нормализация: вытащить текст сценария в блоки, распарсить комментарии, определить
  `brandPreset`, вытащить `manifest` предыдущей версии (для итеративной правки).
- Помечает строку `Status = Generating`, кладёт задачу в очередь.
- **Границы:** только чтение + смена статуса. Никакой бизнес-логики раскладки.

### 3. Planner — сценарий → manifest (ядро, `05-generation-pipeline.md`)
- Вход: `{ scriptBlocks[], comments[], brandPreset, prevManifest? }`.
- LLM-шаг (`openai`): по каждому смысловому блоку выбирает пресет из `registry.ts`,
  назначает `duration` (эвристики тайминга), маппит текст в `data` пресета.
- Детерминированный слой: подстановка токенов, применение комментариев как патчей,
  сохранение непринятых сцен при повторной генерации.
- Выход: строка `src/videos/video-XX.ts` (валидный TypeScript-модуль).
- **Границы:** не пишет пиксели, не создаёт пресеты, работает только с тем, что есть
  в `registry.ts`. Если контента не хватает под существующие пресеты — возвращает
  `Needs fix` с объяснением, а не выдумывает.

### 4. Validator — проверка manifest
Прогоняет чек-лист из `CLAUDE.md`:
- `npx tsc --noEmit` — ноль ошибок (типобезопасность манифеста).
- `TOTAL_FRAMES` == сумма `duration`.
- safe-зоны пусты (`grep`).
- `npm run dev` собирается без ошибок бандла.
Провал → задача в `Error` с логом, без рендера.

### 5. Render — manifest → .mp4
- Headless Remotion render (`@remotion/renderer` через Node API, не CLI — конфиг не
  применяется, опции передаются напрямую).
- Вход: id композиции + `inputProps: { manifest }`.
- Выход: `.mp4` 1080×1920, H.264.
- Позже: кеш по хешу манифеста (не перерендеривать неизменившееся).

### 6. Delivery — результат обратно в Notion
- Заливка `.mp4` на хостинг (определить в M2: S3 / Bunny / Notion file upload).
- Обновление строки: `Video URL`, `Preview`, `Render log`, `Status = Done`.
- При ошибке любого шага: `Status = Error` + `Render log`.

### 7. Render-слой (`project1/`) — уже построен
React-компоненты, которые Remotion превращает в кадры. Планировщик и оркестрация
его **не трогают кодом** — только передают `manifest` как `inputProps`.
Единицы: `presets/` (блоки), `primitives/` (анимация), `design-system/` (токены),
`grid.ts` (зоны), `SceneFrame` (рендерер манифеста).

## Где разместить новый код

Предлагается (уточнить при старте M1):

```
vibe-starter/
  service/                 # ← новый: оркестрация вне Remotion
    ingest/                #   поллинг Notion, нормализация
    planner/               #   LLM + сборка manifest
    validator/             #   прогон чек-листа
    render/                #   headless Remotion render
    delivery/              #   загрузка + запись в Notion
    queue.ts               #   очередь задач (in-memory → BullMQ/SQS позже)
    config.ts              #   ключи, эндпоинты (из env, не в репо)
  project1/                # render-слой, без изменений интерфейса
```

Альтернатива — вынести `service/` в отдельный пакет монорепозитория. Решение
привязано к пункту техдолга про git-структуру (`02-current-state.md` §4).

## Открытые архитектурные вопросы

1. **Хостинг рендера.** Локальный Node-процесс на M1; дальше — Remotion Lambda /
   свой воркер / Render.com. Влияет на время и стоимость ролика.
2. **Хранилище .mp4.** S3-совместимое vs загрузка файла в Notion напрямую (лимиты).
3. **Триггер Ingest.** Поллинг (просто, лаг) vs Notion webhooks (сложнее, мгновенно).
4. **Идентификатор ролика.** `video-XX.ts` по счётчику плохо масштабируется —
   перейти на `video-<notionPageId>.ts` или генерировать манифест в память без файла.
5. **Версионирование манифеста** для итеративных правок — хранить в Notion (свойство
   `Manifest JSON`) или в репо / БД сервиса.
6. **Мультибренд.** Один `tokens.ts` сейчас. Для нескольких брендов — фабрика токенов
   по `brandPreset` (M4).
